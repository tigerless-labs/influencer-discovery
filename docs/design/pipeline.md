# 流水线

五个阶段,一条直线,没有回路。流水线止于**拿到联系方式**——发信、分层、成交跟踪都不在内。

1. **发现** —— 从种子出发抓候选,按渠道形态决定怎么走、何时停。见 [discovery.md](discovery.md)。
2. **求键** —— 从主页链接解析。**解析不出不丢弃**,继续往下走。见 [identity.md](identity.md)。
3. **预筛** —— 已有链接键的先查一道,命中即丢。
4. **抓联系方式** —— 两跳:平台页到本人站点。见 [data-layer.md](data-layer.md)。
5. **落表** —— 用全部可用的键做终筛,追加新行。见 [sheet-contract.md](sheet-contract.md)。

**正确性只由第五阶段保证。** 第三阶段是可省的优化,只为省抓取成本——去重本就发生在两个时点,
因为两个键不在同一时刻拿到。

## 设计不变量

- **只追加,不修改。** 流水线创建新行,永不改动任何已存在的格。人爱改哪列改哪列——不会冲突,
  因为它从不回头。这一条替代了逐列声明所有权。
- **显示名永不作键。** 人会改名换头像,链接与地址里的标识符不会。
- **宁可留空,不可编造。** 身份能定就写;联系方式取不到就留空——留空的含义是「试过、没找到」,
  比猜一个地址安全得多。

## 运行报告

每轮跑完产出一份报告,本地文件,不进 Sheet。它既是**给人的待办**,也是 **agent 决策的账**:

- **两个键都没有的记录**及其原始信息。人补一条线索,下轮它就能去重。
- **取数失败的地址**。路径日志刻意不记网络类失败(见 [data-layer.md](data-layer.md)),
  报告是它们唯一的痕迹;不记就是静默丢失。
- **被丢弃记录的键**。丢弃不留存内容,但键要留——清单若把两个人算成同一个键,
  有这份列表,误杀才是可查的。
- **发现阶段的决策与停止原因**。策略交给 agent,所以它选了什么、为什么停,必须看得见。
- 各阶段的进出计数。

报告可重算:删掉只丢这一轮的账,重跑会重新生成。
