# 流水线

八个阶段单向推进,每阶段的产出是下阶段的唯一输入。任何阶段可单独重跑;同样的输入必须得到
同样的产出。最后一阶段把人的编辑转回事件,回路闭合——这是流水线而非一次性脚本的原因。

1. **发现** —— 渠道 adapter 按配置抓取候选。渠道差异只住 adapter,注册表决定启用哪些。
   产出是带来源与抓取时点的原始记录,不做清洗。
2. **规范化** —— 把异构渠道字段映射到统一的目标实体。映射在配置里,不在代码里。
3. **身份** —— 求稳定键并跨渠道合并同一人。见 [identity.md](identity.md)。
4. **富化** —— 补受众规模、主题域、可达联系方式。每个字段独立携带来源与观测时点;
   不同字段可以来自不同渠道、不同时点,不强行拉平。
5. **分层** —— 给出层级与优先级。见 [tiering.md](tiering.md)。
6. **状态** —— 由事件推导每个目标当前所处的阶段。
7. **投影** —— 把机算结果写进 Sheet 的机算列。见 [sheet-contract.md](sheet-contract.md)。
8. **对账** —— 读回人填列,转成事件喂回状态阶段。

## 设计不变量

- **人填与机算分区。** 每一列的所有权唯一:要么流水线写,要么人写,绝不双写。越界即中止。
- **显示名永不作键。** 人会改名换头像,平台原生标识符不会。
- **状态由事件推导。** 不存在「把状态改成 X」的操作,只有「记录发生了 Y」。状态可以从事件
  重算出来,反之不行——所以事件是权威,状态是缓存。
- **每个观测带来源与时点。** 取不到来源的值不是观测,是猜测,不进流水线。
- **写 Sheet 只进不覆。** 写入前校验表头与行锚,对不上即中止;绝不整表覆盖。
- **联系人数据不落 repo。** 真人信息只住 Sheet,中间态留在本地不入库。
- **失败安全。** 校验不过的记录进失败表,不进主表。宁可少一个目标,不可混入一个错的人。
