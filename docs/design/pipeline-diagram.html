找到人，拿到联系方式，到此为止

五个阶段，一条直线，没有回路。难的从来不是抓，是不重复抓—— 同一个人换个平台、换个页面、换个写法就会被当成新人。所以身份的键从主页链接解析而来， 绝不用显示名；每一行落表前对照全表查两道。

完整流水线

去重排在抓取之前——先筛掉已知的，再花抓取成本。三条虚线是三种「不入表」的去处。

键怎么解析

全部逻辑就一个问题：这个域名是不是这个人独占的？

五个阶段

#阶段做什么不入表的去处
01发现渠道 adapter 按配置抓候选，经取数层出去—
02求键从主页链接解析稳定键，归一化后比对无键 → 运行报告
03去重第一道：键命中目标表现有行即丢弃已知 → 丢弃
04抓联系方式两跳：平台页 → 本人站点。第二道：地址命中即丢弃重复 → 丢弃
05追加只往目标表追加新行，抓不到地址的留空写入—

三条不变量

上一版有七条，其中三条是在给「列所有权」打补丁。改成只追加之后，它们塌成了一条。

  • 只追加，不修改流水线创建新行，永不改动任何已存在的格。人爱改哪列改哪列——不会冲突，因为它从不回头。
  • 显示名永不作键人会改名换头像，主页链接里的标识符不会。
  • 宁可留空，不可编造身份能定就写；地址取不到就留空——留空的含义是「试过、没找到」，比猜一个安全得多。

范围

划出去的比留下的多。每一条都有理由，不是没想到。

在范围内

  • 视频站公开频道页
  • 赞助位市场公开目录
  • 个人站与 newsletter 自有域名
  • 两跳抓取：平台页 → 本人站点

范围之外

  • 发信、话术、分层排序
  • 成交跟踪、点击结算、付款
  • 认证墙后的平台——等合并后随取数层一起获得
  • 两表双向同步——只有人的自然流动

为什么写目标表而不是联系记录表

这条流水线从不联系任何人。目标表是实体表，一行一个人，回答 「这是谁、怎么够得着」——正是它的产出。联系记录表是事件表，一行一次联系；往那里追加几百行， 等于凭空创造几百次没发生过的联系。

目标表之所以看起来「没在用」，是因为没有东西持续往里填，人只好直接在联系记录表上干活。 流水线正是那个持续填充的东西——它是复活目标表的理由，不是绕开它的理由。
