tigerless-labs / outreach

找到人，拿到联系方式，到此为止

这个 skill 只负责三件事：打通数据层、记录规范、防重复。 其余都是读写操作。难的从来不是抓，是不重复抓——同一个人换个平台、换个页面、 换个写法就会被当成新人。所以身份有两个来源的键：主页链接解析出的，和联系方式本身。 一个精确但不总有，一个总有但不总精确。

完整流水线

去重发生在两个时点，因为两个键不在同一时刻拿到。第三阶段只为省抓取成本， 正确性由第五阶段独自保证。

键的两个来源

先看链接怎么解析——判断只有一个问题：这个域名是不是这个人独占的？

五个阶段

#阶段做什么不入表的去处
01发现从种子出发，按渠道形态决定怎么走、何时停—
02求键从主页链接解析。解析不出不丢弃，继续往下走—
03预筛已有链接键的先查一道，命中即丢丢弃（不留存）
04抓联系方式两跳：平台页 → 本人站点—
05落表用全部可用的键做终筛，追加新行；抓不到地址的留空写入丢弃；两键皆无 → 报告

顺序：定脉络，不定细节

使用者给一个总数。怎么花掉它，由 agent 多角度权衡后自己规划——权衡什么， 使用时才定。

设计定死

  • 每轮有边界——总数由使用者给，没有边界不许上线
  • 停止原因可区分：翻到底 / 取够 / 连续无新
  • 召回顺序跟随平台，不重排它给的结果
  • 不做图遍历扩散

使用时才定

  • 要规模，还是要主题贴合
  • 要成功率，还是要平台多样性
  • 总数怎么在各平台间分配
  • 先跑哪个、低产时换不换

为什么不焊死

  • 每轮的意图不同——把某个特征写进配置，等于让上一轮的意图绑架下一轮
  • 代价是不可预测，所以约束靠记录，不靠预先规定
  • 计划、实际、偏离、停止原因，全部进运行报告

三条不变量

最早有七条，其中三条是在给「列所有权」打补丁。改成只追加之后，它们塌成了一条。

  • 只追加，不修改流水线创建新行，永不改动任何已存在的格。人爱改哪列改哪列——不会冲突，因为它从不回头。
  • 显示名永不作键人会改名换头像，链接与地址里的标识符不会。
  • 宁可留空，不可编造身份能定就写；地址取不到就留空——留空的含义是「试过、没找到」，比猜一个安全得多。

为什么写目标表而不是联系记录表

这条流水线从不联系任何人。目标表是实体表，一行一个人，回答 「这是谁、怎么够得着」——正是它的产出。联系记录表是事件表，一行一次联系；往那里追加几百行， 等于凭空创造几百次没发生过的联系。

目标表之所以看起来「没在用」，是因为没有东西持续往里填，人只好直接在联系记录表上干活。 流水线正是那个持续填充的东西——它是复活目标表的理由，不是绕开它的理由。
