# 设计文档索引

这个 skill 只负责三件事:**打通数据层、记录规范、防重复**。其余都是读写操作。

- [platforms.md](platforms.md) —— 打通:每个平台从哪进、怎么走、什么时候停。
- [records.md](records.md) —— 记录规范:log 记什么、表里写什么、报告记什么。
- [dedup.md](dedup.md) —— 防重复:一条规则,一个前提。
- [storage.md](storage.md) —— 这些记录住在哪、长什么形状。

## 这里不写渠道做法

具体到某个平台的联系方式在哪一页、从哪个入口进、页面长什么样,归 `skills/outreach/`——
那是运维手册,会随平台改版而变。这里只写不随平台变的东西:两类形态、停止语义、两跳、取数规矩。

分界线是**变化频率**:平台一次改版就要改的,不该住在讲理由的文档里。

## 流程

使用者给一个数,指的是**最终合格的行数**,不是爬多少个。

```
循环 {
  发现一批候选        agent 自己规划顺序
  查 log,见过的跳过
  抓联系方式          平台页 → 本人站点
  记 log             不管抓没抓到都记
  合格的进目标表       有联系方式 且 符合要求
}
```

累积循环,没有反馈——没有任何东西流回上游。

## 不变量

- **只追加,不修改。** 目标表创建新行,永不改动任何已存在的格。
- **log 记全部,表只记合格的。** 抓不到联系方式的人只进 log。
- **失败不记 log。** 超时、限流、网络错不算「爬过」——记了,一次抖动就永久丢掉一个目标。
- **宁可不进表,不可编造。** 联系方式抓不到就不进表,不猜一个。

## 范围

止于拿到联系方式。发信、分层、成交跟踪、点击结算都在外面。

要多少、优先什么、「符合要求」的门槛、先跑哪个平台——**使用时再定**,不写进配置。
每轮意图不同,焊死等于让上一轮绑架下一轮。设计只保证这些决定留得下痕迹。

## 谁算目标 —— 这条不是旋钮

**能替我们分发的对象。** 判据是**自带受众**,分三级:

- **有受众的人** —— 主目标。
- **做分发的站** —— 不是个人,但产出是把东西推给别人。
- **做自己产品的对象** —— **不进表**,只进 log。

前两级进表,第三级不进。它和「使用时再定」的门槛不同层:主题、规模、平台偏好每轮都变,
**有没有分发能力不变**——没有受众的对象,任何一轮都用不上。焊在设计里不会绑架下一轮。

这条是准入的第二个闸门,与「有联系方式」并列。抓到了地址但对象没有受众,
**是误报,不是产出**。

## 档位的次序按分发所得,不按抓取成本

**不是价格。** 免 key 的那几档抓取成本都是零,分不出高下;合作成本一个数都没有。

**也不是卖方比例** —— 一个渠道都还没测,现有的两个数(一个渠道过半是买方、另一个零买方)
相距太远,不能拿来排序。

**是同一个人在哪里发,我们借到多大的面。** 发在大平台上借得到那个域名的权重,
发在个人站上借不到。所以「大平台」整体排在「个人主场」之前 ——
即使个人主场那边的人自有域名比例更高。

每轮要多少、先跑哪个,仍然使用时再定;固定下来的只有档位之间的次序。

**档位也是运行时的范围选择** —— 一轮可以只跑前几档。但档位归属不因此变成新的配置事实:
权威源仍是 `skills/outreach/` 里 methodology 的目录,配置只存**指向那份文档的路径**,
档位从路径推出。存一份档位号就有两个权威源,而挪动文件时没人会回头改配置。
