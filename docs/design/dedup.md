# 防重复

一条规则:**新候选的 `(人, 平台)` 在 log 里出现过,就跳过。**

没有键的解析,没有 URL 归一化,没有共享域名清单。

## 为什么这样够

在现有目标表上实测:同一个 `(名字, 平台)` 指向多个不同链接的情况**一次都没有**——
而「不同人算成一个」正是那个永远看不见的错误方向。

反过来,按 URL 去重会**误杀**:同一个站点下常常住着不同的人——播客的两位主持人、
公司官方账号与创始人个人、同一平台下的不同板块。实测能去掉的冗余行里,绝大部分是这种误合并,
真重复只是零头。

联系方式也不作依据。面向职能而非个人的那类地址会把一家公司的多个人塌成一个,
是同一个错误的另一种形态。

## 前提

log 里的「人」是**机器从平台页抓的显示名**,不是人手打的——这是它误合并为零的原因。
哪天某个平台的显示名不稳定,这条假设就破,那个平台得单独处理。

## 代价

两个,都是「多一点」而不是「丢东西」:

- 同一个人跨平台出现 → 目标表两行。方向安全,人看得见。
- 同一个人在同一平台改了名 → 白抓一次。

## 一个 log,两类条目

log 也记**走过的地址**。第二跳落在那些个人站点、列表页、聚合页、死链上,大多不产生新行,
却每轮都要重走;`(人, 平台)` 管不到它们。

两类条目规则相同——见过就跳过,失败不记。分成两个文件没有收益。
