# 发现

发现回答「从哪开始、按什么走、什么时候停」。怎么把东西取回来归 [data-layer.md](data-layer.md),
这里只管取什么。

## 渠道分两类形态

**目录型** —— 有限、可枚举、自带边界(赞助位市场那类目录)。翻到底即完。
**搜索型** —— 无边界。边界必须从外面给,否则会一直跑下去。

两类的停止语义不同,是架构分叉,不是配置差异:同一套 adapter 接口下,目录型的「完了」是事实,
搜索型的「完了」是决定。

## 必须成立的

- **每轮有边界。** 没有边界的抓取不许上线。边界的**值**是旋钮,边界的**存在**不是。
- **停止原因可区分。** 翻到底、撞上限、连续无新——三者意味着完全不同的事:渠道枯了、还有货、
  收益递减。混成一句「本轮结束」,就再也看不出哪个渠道值得继续投。停止原因进运行报告。
- **顺序跟随平台。** 相关度、时间、热度由平台给;我们没有更好的判断,自己重排是无根据的。
- **不做图遍历扩散。** 从已知目标找「相关目标」再往外走没有边界,且会漂到不相关领域。
  要做得先有明确的相关性门槛,现在没有。

## 策略交给 agent

具体走法——这轮用哪些查询词、翻几页、先跑哪个渠道、低产时换不换词——是**运行时判断**,
不预先规定。设计只框住边界与停止语义。

代价是这些判断不可预测,所以**约束靠可审查,不靠预先规定**:agent 选了什么、为什么停,
连同停止原因写进运行报告,人事后看得见。

配置持有的是**边界**——渠道开关、每轮配额上限、种子的初始值;不是**策略**。
