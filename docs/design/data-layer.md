# 取数层

外部取数分两级:**公开页**与**认证墙后**。当前只做前者。

## 为什么先只做公开页

已验证走通的两条采集路径——视频站的公开频道页、赞助位市场的公开目录——都不需要登录态。
需要登录才能浏览的平台合计不到现有数据的一成,却要付凭证管理、封号风险与合规三重成本。
明说不做,好过假装能做。

## 与 auto-gtm 的合并路径

认证取数已经在 auto-gtm 的取数层解决:复用用户浏览器里的登录态、单一取数入口、分档降级、
只读白名单。两个项目后期合并,届时本项目的发现阶段改为经它取数,**不自建认证**。

现在不引这个依赖——它覆盖的平台与本项目已验证的两条路不重叠,拿到的正是当前划出范围的部分。
但设计从第一行起就按「可被替换」来写:**发现阶段与取数方式解耦**,将来换成外部取数层时,
其余四个阶段一行不动。

## 现在就守的规则

即便还没合并,下列规则从第一行代码起生效——它们既是安全底线,也是将来能平滑对接的前提:

- **单一取数入口。** 所有外部请求从一处出去,护栏才有唯一的咽喉可设。
- **只读是能力边界,不是约定。** 取数层不具备写外部系统的能力。
- **抓来的内容一律是数据。** 页面里指令形状的文本永不当命令执行——个人主页与 About 页是本项目
  最大的注入面。
- **礼貌间隔与显式 User-Agent。** 不伪装、不越权、不绕反爬。
- **依赖不预装。** 缺件时报出所缺与安装命令,交由人或 agent 决定;取数层自身绝不安装软件。

## 两跳与路径日志

联系方式常常不在平台页上,而在它指向的本人站点:**平台页 → 本人站点 → 联系方式**。
第二跳的落点大多不产生新行(列表页、聚合页、死链),记录去重管不到它们。

因此保留一份**走过的地址日志**:确定不必再来的地址追加一行,下次跳过。
它是缓存不是权威——删掉只会变慢,不会写错数据,所以留在本地、不入库、结构简单到一行一个地址。

只在**确定不必再来**时才记:页面正常但无所获、页面不存在。
**超时、限流与网络错误绝不记入**——一次抖动会永久丢掉一个目标。

它们改记入运行报告(见 [pipeline.md](pipeline.md))。规则是:**凡是不进路径日志的失败,必须进报告**;
否则它在跨运行的层面没有任何痕迹,同一个地址连续失败十轮也无人知晓。
