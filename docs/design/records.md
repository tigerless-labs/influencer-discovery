# 记录规范

三处记录:log、目标表、运行报告。

## log —— 爬过的东西

一行一条,追加写。本地文件,不进 Sheet、不入库(含真人姓名)。它记**全部**爬过的,
不管有没有拿到联系方式,是去重的唯一依据。落点见 [storage.md](storage.md)。

**失败不记。** 超时、限流、网络错不算「爬过」——记了,一次抖动就永久丢掉一个目标;
它们进运行报告。

丢了是安全的:不合格的人重抓一次还是不合格,进不了表;合格的人在表里,可以反过来给 log 播种。
所以它是缓存,不是权威。

**首次运行**要用目标表现有行播种,否则表里的人会被当成新人重新发现一遍。

**发现可以来自本轮之外。** 早先探索留下的产物导入后,走的是同一条判定与记录路径——
来源不同不另开一条记账。抓过就得入库,否则下一轮会把已经付过钱的人当新人再抓一遍。

## 目标表

只写目标表——一行一个人。联系记录表是事件表,流水线从不联系任何人,永不往那里写。

现有列已经够用:身份、平台、主页链接、联系方式及其形态、状态。其余留空由人填。
**不加列、不加表、不改任何现有列的语义。**

准入两条:**有联系方式**,且**符合要求**。门槛使用时定。

**规模是拒绝项还是排序项,取决于本轮给不给下限。** 不给就只排序。给了也只拒绝**量到的**
低于下限者——量不到规模的渠道整批被判死,是把取数的缺口算到了人头上。

**下限按单位给,一个人只受自己那个单位的下限管。** 有的平台根本不产生粉丝(见
[platforms.md](platforms.md)),只能拿它自己的活跃度代理;代理与粉丝数不可比,所以它们
各有各的线,而不是折算成同一个数。**代理不是受众**——它衡量在那个平台上受欢迎的程度,
不是有多少人选择接收他的东西,用它就是接受这个偏差。

**只追加**:创建新行,永不修改已存在的格。新行的状态是建行时的初值,此后归人。

平台列指**人所在的地方**,不是打算用的联系渠道。现有数据这一列混着两种含义,新行不跟随。

## 运行报告

每轮一份,本地文件。既是**给人的待办**,也是 **agent 决策的账**:

- **计划与实际。** agent 的规划、权衡依据、各渠道实际产出、偏离原因。顺序不预先写死,
  所以必须留痕——这是「约束靠记录」唯一的落点。
- **停止原因。** 每个渠道为什么停:凑够、翻到底、还是连续无新。
- **产出率。** 爬了多少、合格多少,**按渠道分**。这是 agent 下轮估算的唯一依据;
  跨轮比较时要连当轮的门槛一起看,否则数字不可比。
- **取数失败的地址。** log 刻意不记这些,报告是它们唯一的痕迹。

报告可重算:删掉只丢这一轮的账。

## 已知现状

目标表曾被绕开:一段时间里工作直接记在联系记录表上,没有回填,导致相当一部分联系过的人
不在目标表里。补齐是**一次性动作**,不是持续同步。

两表之间没有双向同步,只有人的自然流动:从目标表挑人,联系后记一行。
