# 记录规范

两处记录:表里的行,和运行报告。

## 表

只写**目标表**——一行一个人,回答「这是谁、怎么够得着」。联系记录表是事件表,一行一次联系;
流水线从不联系任何人,所以永不往那里写。

现有列已经够用:身份、平台、主页链接、联系方式及其形态、状态。其余留空由人填。
**不加列、不加表、不改任何现有列的语义。**

**只追加**:创建新行,永不修改已存在的格。新行的状态是建行时的初值,此后归人。

平台列指**人所在的地方**,不是打算用的联系渠道。现有数据这一列混着两种含义,新行不跟随。

## 运行报告

每轮一份,本地文件,不进 Sheet。它既是**给人的待办**,也是 **agent 决策的账**:

- **计划与实际。** agent 的规划、权衡依据、各渠道实际产出、偏离原因。顺序不预先写死,
  所以它必须留痕——这是「约束靠记录」唯一的落点。
- **停止原因。** 每个渠道为什么停:翻到底、取够、还是连续无新。
- **两个键都没有的记录**及其原始信息。人补一条线索,下轮它就能去重。
- **取数失败的地址。** 路径日志刻意不记网络类失败,报告是它们唯一的痕迹;不记就是静默丢失。
- **被丢弃记录的键。** 丢弃不留存内容,键要留——清单若把两个人算成同一个键,
  有这份列表,误杀才是可查的。

报告可重算:删掉只丢这一轮的账,重跑会重新生成。

## 已知现状

目标表曾被绕开:一段时间里工作直接记在联系记录表上,没有回填,导致相当一部分联系过的人
不在目标表里。补齐是**一次性动作**,不是持续同步。

两表之间没有双向同步,只有人的自然流动:从目标表挑人,联系后记一行。
