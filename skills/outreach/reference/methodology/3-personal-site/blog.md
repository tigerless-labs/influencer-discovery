# Blog

个人技术博客。和 Newsletter 的区别:**没有赞助入口这条捷径**;和 Website 的区别:
**博客是个人的**,拿到的地址算这个人的。

**个人站比公司博客更不留邮箱** —— 目标表里那批(偏公司博客)六成有邮箱,
从零发现的真·个人站只有四成。别拿前者的数字估后者。

## 入口

**四个免 key 的源,没有一个挡诚实爬虫。要交叉用,因为它们的偏性正好互补:**

- **个人站目录**(personalsit.es、blogroll.org、indieblog.page)—— 给「个人」,
  但**不筛技术**。一轮就能出上千个域名。
- **技术社区**(Hacker News 的 Algolia 接口、Lobsters 的 JSON feed)—— 给「技术」,
  但**不筛个人**。靠**同域名的投稿频次**过滤:只投过一两次的基本是个人博客,
  高频的是媒体。两个社区之间几乎不重叠,不是彼此的子集。

Lobsters 的 story JSON 里有一个字段直接标注「投稿人就是作者」 ——
**这是整条链上唯一确定性的「站点 → 人」绑定**,不用猜。

从 blogroll 往外走要克制 —— 那是图遍历,设计文档已排除无边界扩散。

### 还没跑但已确认可达的源

都是免 key、对诚实爬虫开着的,**只验过取得回,没验过产出**:

- **Kagi 的 Small Web feed** —— 专收个人小站的机器可读源,一次返回上百个域名。
  偏性和个人站目录相同,是那一类里体量最大的一个。
- **Bear Blog 与 micro.blog 的公开发现页** —— 托管型个人博客的站内榜单。
- **ooh.directory** —— 分类目录,首页只挂当日更新,要按分类翻;以非技术博客为主。
- **垂类榜单站**(某某领域 Top 100 博客那种)—— 一页给上百个域名,
  但它们是**名录页**,要按名录源单独跑,不能当第二跳落点,
  理由见 [landing-page-two-hop.md](../_shared/landing-page-two-hop.md)。

## 拿联系方式

按顺序,后一档只处理前一档没解决的:

**① 首页。** 三分之二的命中出在这里(个人站把邮箱和社交放页脚)。先抠首页,再决定进不进子页。

**② 站上的联系页。** `/about` 几乎每个站都有,`/contact` 只有三分之一有,
但两者的**产出**差不多 —— 存在率高不等于产量高。

**③ 格式化文件。** 只有 `/humans.txt` 与 `/.well-known/security.txt` 值得试 ——
**它们的格式本身就要求写联系方式**。`/now` `/uses` `/colophon` `/links` 抠到的
只是页脚的重复,新邮箱为零。这一档整体只能救回不到一成的无邮箱站。

**这些路径返回 200 的有约一成是软 404,必须按内容判,不能按状态码判。**

**④ GitHub 一跳。** 一半的博客链到 GitHub,那些个人账号里四成有公开邮箱 ——
**能把无邮箱的站救回约两成,是这条链上最大的一块补丁**,应排在社交兜底之前。
`*.github.io` 的域名前缀直接就是用户名,不用先在页面里找链接。

**⑤ 域名注册信息。** 只对 `.com/.net/.org` —— 个人博客最爱用的 `.io` `.me` `.co`
和各国后缀根本查不到。**必须串行**,并发就被限流。滤掉注册商的隐私转发地址后仍有两成
能拿到个人邮箱。**注意它给的是域名注册人,不必然是作者本人,写进表要标来源。**

**⑥ 社交兜底。** 到这一步还没有邮箱的,记社交 handle。个人技术博客上 Mastodon 的
出现率比预想高得多。

## 混淆即到此为止

contact 页要点击才显示邮箱,或者用了 Cloudflare 那类邮箱混淆 —— **都不解。**

**能解不构成该解。** 站主开这个功能的唯一目的就是让爬虫抠不到,判据是**对方的意图**,
不是技术难度。代价明确:约百分之四的站,落到社交兜底。

## RSS 给人名,不给邮箱

**邮箱位是死的** —— `managingEditor` 与 `webMaster` 在两批完全不同的个人站上各验一次,
仍然是零。

**但人名位是全链最好的。** `<author>` / `<dc:creator>` 有七成带作者姓名,
覆盖率远高于 `<meta name="author">` 和 JSON-LD 的 `Person` 节点。
这正是去重键缺的那一半,见下。

同理,JSON-LD 作为**邮箱**来源没有价值(命中的都和首页重复),作为**身份**来源有价值。

## 发布社区不是博客

**注册就能发、无编辑门槛的写作平台。** 和个人博客的区别:**站不是他的** ——
页脚没有他的邮箱,联系方式只能从资料页或他自己的域名走第二跳。

| 平台 | 归属 |
|---|---|
| Medium | 不做 —— 平台上没有联系方式,资料页对 CLI 关着门 |
| Substack | [newsletter.md](newsletter.md) —— 那一档有赞助入口这条捷径 |
| DEV.to | [2-blog-platform/dev-to.md](../2-blog-platform/dev-to.md) —— 已跑通 |
| Hashnode | [2-blog-platform/hashnode.md](../2-blog-platform/hashnode.md) —— 未跑通 |
| freeCodeCamp News | 未跑通;有编辑审,介于社区与媒体之间 |
| HackerNoon | 未跑通;有编辑审,AI 垂类密度高,同上介于社区与媒体 |
| WordPress.com | 未跑通;体量最大的一个,自带公开的标签与阅读器入口 |
| Tumblr | 未跑通 |
| Mirror / Paragraph | 未跑通;写作者集中在加密垂类 |

**托管型个人博客不在这张表里。** Bear Blog、micro.blog、write.as、Ghost 这类
**站是他自己的**(自定义域名、页脚是他的),按个人博客处理 ——
其中 Bear Blog 与 micro.blog 还各有一个公开的发现页,归上面「入口」那一节。

**Hacker News 与 Lobsters 不在这张表里** —— 它们不承载文章,是上面「入口」那一节的发现源。

**体量最大的两个已单列**,归 `2-blog-platform/`。这张表剩下的都未跑通。

社区上的人几乎都在别处有主场 —— **从个人博客或 newsletter 发现同一个人更便宜**,
所以在这张表里出现不等于要从这里进。

## 停止语义

搜索型 —— **连续无新**。

## 去重的键

`(作者显示名, Blog)`。

**显示名按覆盖率排,优先取 RSS 的 `<author>` / `<dc:creator>`**,其次 `<meta name="author">`、
JSON-LD 的 `Person`,最后用 GitHub 账号的真名兜底。要从页面抓,不是从域名猜。

**同一个域名下可能有多个作者**(团队博客、公司工程博客),按域名判重会把他们塌成一个 ——
这正是设计文档说的按 URL 去重的误杀。**多作者站不归这里**:媒体见 [media.md](../_not-run/media.md),
公司工程博客属于产品站,不进表。

## 边界

- 静态站居多,没有 CDN,礼貌间隔要足;查域名注册信息要串行。
- 第三方的订阅/联系/预约组件**不泄漏站主邮箱**,收件地址在服务端,别去解析它们。
- 有的博客只有社交没有邮箱,那就只能记社交 handle 作为联系方式形态。
- 个人博客的域名会换,历史链接会死 —— 死链进运行报告,不进 log。

## 待验证

- 发现入口产出的域名还没过卖买判别,也没验和目标表现有行的重合度。
- Lobsters 的资料页接口限流较紧,礼貌间隔要多大还没测出来。
