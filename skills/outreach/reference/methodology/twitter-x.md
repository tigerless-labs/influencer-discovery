# X / Twitter

做不做、怎么取,见 [../datalayer/twitter-x.md](../datalayer/twitter-x.md)。
这里只写取到之后怎么拿联系方式。

## 这里没有邮箱字段

能拿到的是 bio 文本和一个外链。联系方式要么是创作者自己写在 bio 里的,
要么在外链的落点 —— 也就是说这个平台**只是第二跳的又一个起点**,
见 [landing-page-two-hop.md](landing-page-two-hop.md)。

## 现在的实际角色:第二跳的落点

目标表里的 X 行不是在 X 上发现的,是从个人站、GitHub、YouTube 链接区顺过来的。
这一路不需要取数层:**记下 profile URL 作为联系方式形态,不解析页面。**

`Contact Method = Twitter DM`,`Contact Info` 是 profile URL。
**这不是一个已验证可达的地址,只是一条可用的路径。**

## 打通之后会变成什么

发现能力是真的 —— 搜索能从话题找到人,这是它和 LinkedIn 的根本区别
(那边打通了也没有发现这一步,见 [linkedin.md](linkedin.md))。

所以这份的形状会从「第二跳落点」变成「搜索型发现渠道」:停止语义变成**连续无新**,
判重的键变成 `(handle, X)`。handle 唯一且稳定,判重前提扎实。

## 待验证

- bio 文本里写明邮箱的比例。经验上技术垂类高于生活垂类,未在本项目人群上测过。
- 打通后从话题搜到的人,与现有渠道的重合度。
