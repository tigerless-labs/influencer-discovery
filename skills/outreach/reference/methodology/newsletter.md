# Newsletter

目标表里第二大的渠道。和 Blog / Website 的区别在于:**newsletter 普遍自带一个为
赞助商准备的入口**,那个入口比 about 页高产得多。

## 入口

两种来源,性质不同:

- **赞助位市场的目录** —— Passionfroot、Paved。目录型,有边界,翻到底即完。
  见 [passionfroot.md](passionfroot.md)、[paved.md](paved.md)。
- **搜索型发现** —— 从关键词找 newsletter,或从已有目标的「推荐/交换订阅」区出发。
  后者要小心,它是图遍历的一种形态。

## 拿联系方式

**先找赞助入口,再找 about。** 表里的 contact note 反复出现同一句话:走 advertise 页 /
sponsor 页 / editorial 入口。常见路径名:

```
/advertise   /sponsor   /sponsorship   /partner   /work-with-us   /media-kit
```

托管平台的形态各不相同,但都有稳定的落点:

- **Substack** —— `about` 页;作者常把联系方式写在那里。域名形如
  `<name>.substack.com` 或自定义域。
- **Beehiiv / ConvertKit / Ghost** —— 各有自己的固定页面结构。
- **自建** —— 无规律,退回第二跳,见 [landing-page-two-hop.md](landing-page-two-hop.md)。

**每封邮件的页脚**也常带联系方式和实际发信地址,但那要求订阅——**不订阅**,那是写操作,
且会把本项目的身份暴露给目标。

## 判断:个人 newsletter 还是媒体产品

这个区分决定拿到的地址算不算数:

- **个人 newsletter** —— 作者本人的地址,算数。
- **媒体化 newsletter**(有编辑部、有 rate card)—— 拿到的是 `sponsors@` / `advertise@`
  这类面向职能的地址。**对赞助投放有用,对个人 outreach 不算数**,见
  [landing-page-two-hop.md](landing-page-two-hop.md) 的「不算数的东西」。

表里的 contact note 已经明确区分过这两类:有几条写着「适合付费投放,不是个人 outreach」。

## 停止语义

看来源:市场目录来的是**目录型**(翻到底),关键词搜的是**搜索型**(连续无新)。
同一个渠道两种停止语义,报告里必须分开记,否则看不出哪一路还值得投。

## 去重的键

`(newsletter 名, Newsletter)`。

注意同一个人可能既有 newsletter 又有 YouTube 频道 —— 那会落成**两行**,这是设计接受的
代价(方向安全,人看得见),不是 bug。

## 边界

- 大牌 newsletter 的 rate card 常要填表单才给,**不填表单**——那是写操作。
- 「不建议猜测个人邮箱」——表里已有的 contact note 自己写着这句。

## 待验证

- Substack / Beehiiv / Ghost 各自的 about 与 sponsor 页是否有稳定可解析的结构。
- `/advertise` `/sponsor` 这组路径名在目标表现有的 97 行 newsletter 上的实际命中率。
- 赞助位市场目录与关键词搜索的重合度——如果重合很高,搜索这一路可以省掉。
