# Medium

目标表里 4 行,长尾。**Medium 本身不提供联系方式**——它是一个发布平台,
个人资料页只有 bio 和外链。

## 入口

**搜索型。** 按标签或关键词找文章,再取作者。和别处一样,搜内容比搜人更能筛到
真正在写这个主题的人。

Medium 上大量作者是**在别处也有主场的人**(个人博客、newsletter)。所以这个渠道更该被
当作**发现入口**,而不是联系方式来源。

## 拿联系方式

```
文章 → 作者资料页 → bio 文本 + 外链 → 第二跳
```

资料页给的是 bio(短)和一个外链。联系方式几乎必然在外链的落点上,
见 [landing-page-two-hop.md](landing-page-two-hop.md)。

表里已有的 contact note 印证了这一点:两条都写着「Medium 私信/评论」「需核实具体
Medium 主页」——也就是**当时也没在 Medium 上拿到可用的联系方式**。

## 站内私信

`Contact Method = Other`,记 profile URL。是一条路径,不是地址。

## 停止语义

搜索型——**连续无新**。

## 去重的键

`(作者显示名, Medium)`。

Medium 的显示名可改且不唯一,判重前提在这里比 GitHub 弱。若同一批里出现两个同名作者,
这个平台要单独处理——设计文档已经预告过这种情况(见
[dedup.md](../../../../docs/design/dedup.md) 的「前提」)。

## 边界

- 付费墙文章正文取不到,但作者资料页与 bio 不受影响。
- 出版物(publication)不是人。挂在出版物下的文章要取到**文章作者**,不是出版物名。

## 待验证

- 显示名重复在实际样本里出现的频率——判重前提是否需要在这个平台上加强。
- 从 Medium 顺出去的外链有多大比例落在已经在表里的个人站上(即这个渠道是否只是
  在重复发现已知的人)。
