# Medium

**平台上没有联系方式,而且资料页对 CLI 关着门。** 这两条叠加,让它只剩下发现入口的价值。

## 能走通的只有 feed

作者的文章 feed 匿名可取;**资料页、about 页、标签页对 CLI 一律 403**。
资料页偶尔取得回,但初始 HTML 里没有 bio、没有外链 —— 取回了也没有可用的东西。

浏览器能打开 about 页,那里只有一个「Connect with」区,列作者自己填的外链,**填的人不多**。

## 拿联系方式

**没有可靠的路。** feed 里的外链实测几乎全是**引用来源**(论文、公司主页、工具站),
不是作者自己的域名;每个 feed 还带一条托管服务的固定链接,是噪声。
指望从文章正文反推出作者的个人站,这条路不成立。

第一跳的起点只能从别处来。落点的处理见 [landing-page-two-hop.md](landing-page-two-hop.md)。

## 站内私信

`Contact Method = Other`,记 profile URL。是一条路径,不是地址。

## 停止语义

搜索型 —— **连续无新**。标签页要浏览器才能翻。

## 去重的键

`(作者显示名, Medium)`。

Medium 的显示名可改且不唯一,判重前提在这里比 GitHub 弱。若同一批里出现两个同名作者,
这个平台要单独处理——设计文档已经预告过这种情况(见
[dedup.md](../../../../docs/design/dedup.md) 的「前提」)。

## 边界

- 付费墙文章正文取不到。
- 出版物(publication)不是人。挂在出版物下的文章要取到**文章作者**,不是出版物名。
- 大量作者在别处也有主场(个人博客、newsletter),**从那边发现同一个人**。

## 待验证

- 标签页在浏览器里翻一轮能出多少人。在此之前,这一档只处理从别的渠道顺过来的
  Medium 链接,不主动跑。
