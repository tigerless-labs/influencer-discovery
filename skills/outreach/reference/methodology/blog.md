# Blog

个人技术博客。和 Newsletter 的区别:**没有赞助入口这条捷径**,联系方式在 about / contact
页;和 Website 的区别:**博客是个人的**,拿到的地址算这个人的。

## 入口

**搜索型。** 从关键词搜文章,或从聚合站(Hacker News、Lobsters、RSS 目录、
其他博客的 blogroll)出发。

从 blogroll 往外走要克制——那是图遍历,设计文档已排除无边界扩散。

## 拿联系方式

按命中率排:

1. **`/about` 与 `/contact`** —— 最主要的落点。
2. **页脚** —— 个人站常把邮箱和社交图标放在这里,about 页反而没有。
3. **RSS / Atom feed** —— `managingEditor` 和 `webMaster` 字段按规范放邮箱。多数生成器
   不填,但**填了的就是直接可用的地址,不用解析 HTML**。这条零成本,值得每次都试。
4. **社交外链** —— 拿不到邮箱时的退路,进第二跳,
   见 [landing-page-two-hop.md](landing-page-two-hop.md)。

## 一个真实存在的形态:点击 reveal

表里已有的 contact note 记着这种情况:contact 页要点击才显示邮箱。

**这是反爬,到此为止。** 换社交或博客的其他入口,不执行 JS 去取,不拼一个。

## 停止语义

搜索型——**连续无新**。

## 去重的键

`(作者显示名, Blog)`。

博客的作者名要从页面抓,不是从域名猜。**同一个域名下可能有多个作者**(团队博客、
公司工程博客),按域名判重会把他们塌成一个——这正是设计文档说的按 URL 去重的误杀。
团队博客应当归 [website.md](website.md) 处理。

## 边界

- 静态站居多,没有 CDN,礼貌间隔要足。
- 有的博客只有社交没有邮箱,那就只能记社交 handle 作为联系方式形态。
- 个人博客的域名会换,历史链接会死——死链进运行报告,不进 log。

## 待验证

- `managingEditor` / `webMaster` 在目标表现有的 38 行 blog 上的实际填写率。
  猜测很低,但成本为零,值得测一次拿到真实数字。
- 主流静态站生成器(Hugo / Jekyll / Astro / Next)的 about 页有没有可利用的共性。
- 「点击 reveal」这种形态在样本里占多少——如果很少,不值得单独处理;如果不少,
  要在报告里单列一类停止原因。
