# Passionfroot

**不是目录,是解析器。** 公开的那一面只有 `passionfroot.me/<handle>` 这一层:
**已知 handle 就能拿到页面,但拿不到 handle 的清单。**

## 目录这条路不存在

站内的发现入口要 Creator 或 Partner 账号,sitemap 里一条创作者页都没有。
没有账号就没有可枚举的清单 —— **原本以为的「目录型、翻到底即完」不成立**,
这一档因此没有自己的发现能力。

**反向找 handle 也是空的。** 实测扫过近九十个 YouTube 频道的链接区和两百多个创作者
自有站的首页外链,**指向赞助位市场的链接一条都没有** —— 入驻市场的创作者不把这个身份
挂在自己的门面上。链接区那一层被自营社群与打赏占满,他们在那里卖的是自己的社群,
不是广告位。

**所以 handle 只有一个来源:表里已有的历史链接。** 这一档只有存量、没有增量,
而存量正以六成的速度腐坏 —— **它会自然归零**。不要再投入去建 handle 来源。

## 创作者页给什么

页面是服务端渲染的,curl 直接可取。上面有:

- 预订入口(**就是联系方式本身**)
- 可投放的位置、档期、报价
- **相当一部分页面直接写了邮箱** —— 多是 `partnerships@` / `collabs@` 这类招商地址
- 指向本人平台的链接

`Contact Method = Website`,`Contact Info` 就是那个 `passionfroot.me/<handle>` 地址。

**解析外链要先去掉全站共有的那批。** 每一页页尾都挂着 Passionfroot 自己的社交账号,
按域名收集会把它们当成创作者的。判据是**在整批页面里出现的频次** ——
几乎每页都有的一定是站尾。

## 链接会死

表里的历史链接**六成已经 404**。创作者退出或改名,页面就没了。
跑之前先探活,别拿死链去推断这个渠道没产出。

## 交叉链接对判重的影响

从这里拿到某人的 YouTube 链接,**不等于**可以在 YouTube 那一档也记一行。

判重的键是 `(人, 平台)`:同一个人跨平台出现落成多行是设计接受的,
但那应当是**在各平台真实发现**的结果,不是从一份名录里复制出来的。

从这里只产出 `(人, Passionfroot 上填的所在平台)` 一行。交叉链接的正确用途是
**给 log 播种**,让后续在那些平台发现同一个人时能正确跳过。

## 停止语义

**没有。** 它不是发现渠道,只解析已有的 handle。

## 去重的键

`(创作者显示名, 该行的 Platform 值)`。

注意目标表里这些行的 `Platform` 列记的是 **Newsletter / Website**,不是 Passionfroot——
平台列指「人所在的地方」,而市场只是发现他的地方。**别把 Passionfroot 写进平台列。**

## 边界

- 只覆盖主动入驻的创作者。
- 不预订、不填表单、不发消息 —— 全是写操作。
- 定价与档期是商业信息,记进表没有意义(会过期),交给人看页面。
