# Passionfroot

赞助位市场,设计文档说的「已验证的两条路」之二。取数见
[../datalayer/public.md](../datalayer/public.md)。目标表里链接指向 `passionfroot.me` 的行数仅次于 YouTube。

## 这个渠道和别处根本不同的一点

**不用挖联系方式。** 创作者在这里挂的就是「我接赞助,从这里预订」的页面——
页面本身就是联系入口。

所以本渠道的产出形态是:`Contact Method = Website`,`Contact Info` 就是那个
`passionfroot.me/<handle>` 地址。第二跳基本不需要。

## 入口

**目录型。** 有限、可枚举、自带边界。按分类/主题翻,翻到底即完。

这是它相对搜索型渠道最大的优势:「完了」是事实,不是判断。

## 拿联系方式

创作者页上通常带:

- 预订入口(**就是联系方式本身**)
- 可投放的位置与档期
- 受众规模与画像的自述
- 指向本人平台的链接——YouTube 频道、newsletter、社交

**最后一项是这个渠道的隐藏价值:它是一份带交叉链接的名录。**
同一个人在这里能一次拿到多个平台的主页地址,省掉在各平台分别发现的成本。

## 但要小心它对判重的影响

从这里拿到某人的 YouTube 链接,**不等于**可以在 YouTube 那一档也记一行。

判重的键是 `(人, 平台)`:同一个人跨平台出现落成多行是设计接受的,
但那应当是**在各平台真实发现**的结果,不是从一份名录里复制出来的。

从这里只产出 `(人, Passionfroot 上填的所在平台)` 一行。交叉链接的正确用途是
**给 log 播种**,让后续在那些平台发现同一个人时能正确跳过。

## 停止语义

目录型——**翻到底**。

## 去重的键

`(创作者显示名, 该行的 Platform 值)`。

注意目标表里这些行的 `Platform` 列记的是 **Newsletter / Website**,不是 Passionfroot——
平台列指「人所在的地方」,而市场只是发现他的地方。**别把 Passionfroot 写进平台列。**

## 边界

- 只覆盖主动入驻的创作者。没在这里挂牌的人这条路找不到,不是遗漏。
- 不预订、不填表单、不发消息——全是写操作。
- 定价与档期是商业信息,记进表没有意义(会过期),交给人看页面。

## 待验证

- **「翻到底」成立与否取决于目录的实际可翻范围** —— 那是取数层的问题,
  见 [../datalayer/public.md](../datalayer/public.md)。翻不到底的话本渠道退化成搜索型。
- 创作者页的字段是否在初始 HTML 里。
- 页面上交叉链接的填写率——它决定这份名录作为 log 种子的价值。
- 与 [paved.md](paved.md) 的重合度。两个市场都跑一遍是否划算。
